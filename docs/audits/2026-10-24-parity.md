## Findings from this window

1. Cloudflare stored empty API key/account/gateway fields incorrectly fell back
   to ambient values. Empty ambient strings marked present by a custom auth
   context incorrectly produced auth. Source-generated fixtures from
   `providers/cloudflare-auth.ts` reproduced six failures before the fix.
   `TestCloudflareAuthFieldPresenceAgainstUpstream` now passes all nine cases.
2. Cancellation during a Cloudflare environment lookup returned usable auth and
   continued reading configuration. `TestCloudflareAuthStopsAfterCancelledEnvLookup`
   was red (`result present = true, error = <nil>`) and now passes for both
   Cloudflare auth methods, including no subsequent ambient reads.
3. Azure's deployment rewrite HTML-escaped `<`, `>` and `&` with the standard Go
   marshaler instead of preserving JSON.stringify bytes. The payload-hook
   regression failed with `deployment\\u003c\\u0026\\u003e`; it now passes using
   `ai.MarshalJSON`.
4. Azure's deployment wrapper lost its rewrite when a caller payload hook
   returned nil. Upstream `withDeploymentName` uses `?? params`; the regression
   now passes and retains the deployment name.

5. MCP token authentication treated an explicitly empty client secret as
   present. Against public `exchangeAuthorizationCode`, the nine-case
   source-generated token-auth fixture reproduced wrong Basic auth, missing
   client IDs, an unwanted empty `client_secret`, and a missing-secret failure
   that incorrectly sent HTTP. Empty secrets now follow upstream truthiness.
6. MCP token requests included `resource=` for an explicitly empty resource;
   upstream omits it. The same public fixture covers the correction.
7. MCP token error parsing ignored an empty string `error` and instead reported
   `server_error`. `TestTokenRequestPreservesEmptyOAuthErrorCode` reproduced
   the wrong code/description; the server's string error now wins regardless
   of whether it is empty.
8. MCP `WWW-Authenticate` parameter parsing used Go's ASCII whitespace and
   Unicode case folding instead of JavaScript's whitespace and non-Unicode
   `/i` semantics. Eight Unicode/vertical-tab cases missed both scope/error;
   the long-s parameter `ſcope` incorrectly won over `scope`. Both regressions
   passed after correcting the regex; the actual upstream parser confirmed
   all nine cases. Quoted whitespace remains content.
9. MCP structured-only tool results were indented as raw JSON, not
   re-stringified as values. Six source-generated cases reproduced array-index
   property order, number spelling, string escaping and duplicate-member
   differences. They now pass through the shared JavaScript JSON serializer
   before indentation (`TestStructuredToolContentAgainstUpstream`).
10. The typed MCP request-ID decoder accepted null as numeric zero despite
    upstream `isJsonRpcId`. `TestJsonRpcIDUnmarshalRejectsNull` was red and
    passes after requiring a non-null decoded number.
11. Agent proxy options dropped explicit null header values, restoring remote
    provider defaults the caller meant to suppress.
    `TestStreamProxyPreservesNullHeaderOverrides` reproduced the missing wire
    member through a local HTTP peer, and now passes.

12. RPC client event-listener panic killed the stdout reader and the host
    process, whereas upstream catches exceptions around each line dispatch.
    `TestClientListenerFailureDoesNotKillReader` crashed red in `handleLine`;
    after restoring that boundary, both commands receive responses, the second
    listener misses only the throwing event, and `go test -count=1
    ./coding/rpcclient` passes.

13. Built-in goal command parsing used Go trim instead of JavaScript trim:
    BOM-wrapped `status` was rejected, BOM survived in objectives, and NEXT
    LINE around `status` was incorrectly removed. The installed D223 extension
    confirmed the expected values; `TestGoalCommandTrimsJavaScriptWhitespace`
    failed for all three and now passes.
14. Goal objective formatting did not flatten JavaScript Unicode whitespace,
    incorrectly removed NEXT LINE, counted runes rather than UTF-16 units,
    and treated nonpositive limits as unlimited rather than using JS slice.
    Two public `TruncateObjective` regressions reproduced these differences
    before their fixes. Shared JS string helpers now preserve the reference
    cases, including supplementary characters and zero/negative limits.
15. Goal blocking-reason validation accepted a BOM-only reason and rejected a
    NEXT LINE reason, opposite to the installed extension. The public machine
    dispatch regression failed for both, then passed using JS trim.
16. Goal cards measured rune counts before showing expansion hints, hiding
    hints and leaving full bodies when supplementary-character text exceeded
    the reference thresholds. The three public renderer cases failed red and
    now pass using JS length for the same 60/80-unit thresholds.

17. `GoCoalesced("", ...)` permanently retained its key after completion.
    `TestCoalescedEmptyKeyBecomesReusable` failed with one call instead of two;
    explicit coalesced-task bookkeeping now releases even an empty key.
18. The UI blocking analyzer treated `os.Hostname` as a cheap environment call,
    despite its syscall/file-I/O implementation. A public `Find` fixture failed
    to report the UI root, then passed after removing that exemption.
19. Highlight language lookup was case-sensitive, unlike highlight.js. Public
    lookup/highlight tests failed for `Go`, `GO`, `Js`, `TYPESCRIPT` and `AWK`;
    JS lowercase now handles those without falsely accepting `İni`.
20. Repeated `--list-models` flags retained stale union fields. A final bare
    flag still used an earlier search pattern in the CLI. Both last-value forms
    failed red and now reset the opposite field.
21. YAML highlighting used ASCII whitespace in three language rules. Public
    tests reproduced wrong unquoted strings, container strings and document
    marker scopes for EM SPACE; explicit JS classes now match all five cases,
    including NEXT LINE non-whitespace controls.
22. Inline LaTeX omitted backslash-bracket delimiters, accepted empty/multiline
    completed parenthesis spans, and closed at escaped delimiters. Six public
    parser cases pinned upstream behavior before correcting the shared search.
23. Inline LaTeX omitted double-dollar delimiters and could turn a completed
    multiline single-dollar span into pending math. The regression failed for
    closed/pending double-dollar and the multiline case, then passed.
24. Emphasis scanned delimiter characters inside escapes, code spans, HTML
    attributes and link labels. All four public parser examples failed red.
    Restoring Marked's opaque-content mask reduced the seeded inline probe's
    mismatches from 340 to 61 without changing the existing goldens.
25. Strict strikethrough ignored escape-atom boundaries and used Go whitespace.
    Four public examples failed red; reference-compatible escaped atoms and JS
    whitespace now preserve escaped closers and escaped trailing spaces.
26. Unmatched tilde runs were retried from the middle, inventing strikethrough
    in `~~~x~~` and `~~~~x~~`. Three cases failed red before whole-run text
    consumption restored Marked's behavior.

27. Link/image labels retained escaped square brackets, unlike Marked's
    `outputLink`. Both public examples failed red, then matched unescaping
    before recursive inline parsing.
28. Hyperlink labels could contain another explicit hyperlink. The nested-link
    example failed red; a parser-scoped emitted-link flag now rejects the
    outer link while keeping linked images valid.
29. Asterisk closing-delimiter flanking treated tilde as punctuation instead
    of GFM word content. Three minimal cases failed red, then passed.
30. Underscore opening-delimiter classification also treated tilde as
    punctuation, incorrectly allowing an intraword CJK opener. A minimal
    `中文__~~x__` regression failed red and now remains literal text.
31. In-memory MCP sends ran concurrent delivery goroutines, reordering sequential
    messages. The 64-notification public test failed immediately (`0 = 1`), then
    passed 100 repetitions after serialized FIFO draining. Closing discards
    pending deliveries; callbacks remain outside the existing mutex.
32. Infrastructure: the full gate exposed a watchdog helper exiting with Go's
    automatic deadlock dump before SIGQUIT. Targeted retries alone did not
    reproduce it. A 30-second child test alarm prevents that early runtime exit
    and bounds the helper. Twenty repetitions and the next full non-short gate
    passed. This is a Go-only test-harness correction, not upstream parity.
33. MCP SSE decoding failed on a stream-leading BOM and coalesced distinct
    malformed UTF-8 subsequences into one replacement. Four public cases,
    including one-byte readers, failed red; streaming UTF8BOM decoding now
    matches TextDecoder and retains BOMs inside event data.
34. SSE dispatch retained empty event/id metadata while upstream omits it.
    The regression failed red; empty metadata is now absent, but `onId("")`
    still reports the resumption reset.
35. A failing before-tool hook that also canceled the run lost its actual error
    to `Operation aborted`. Public `RunToolCall` failed red; hook failures now
    win before the signal check, matching upstream's throw/catch ordering.
36. A declared skill with a missing description skipped name validation. The
    public loader reported only one warning instead of the reference's three
    for `Bad--Name`; validation now finishes before dropping the skill.
37. SSE consumers accepted LF and CRLF but not bare CR line boundaries.
    `bufio.Scanner`'s default splitter never recognized the CR-only frames that
    OpenAI 7.19.0's `LineDecoder` and upstream `consumeLine` accept, so those
    streams failed
    red three ways: OpenAI Completions reported `stopReason: error`, Responses
    reported "ended before a terminal response event", and Anthropic emitted no
    events. A shared `newSSELineSplitter` now handles CR, LF and CRLF, and emits
    a CR-terminated frame immediately instead of waiting for the next network
    chunk to rule out an LF. A third public test covers that immediate-emission
    property; the first implementation buffered the trailing CR and failed it.
38. Anthropic SSE decoding skipped the reference's streaming `TextDecoder`.
    A stream-leading BOM broke the first field name (one event instead of two),
    and malformed UTF-8 was replaced per byte (`ff ff e2 82` produced four
    replacements instead of three). Both cases failed red through
    `IterateAnthropicEvents`; the body now goes through
    `unicode.UTF8BOM` decoding, matching `TextDecoder`.
39. RPC client event listeners were stored in a Go map, so dispatch order was
    randomized. Upstream iterates a snapshot of an ordered `Set`.
    `TestClientListenersRunInRegistrationOrder` failed red on the second of 25
    round trips (`second,first`); a panicking first listener also let the second
    listener see the failed event, which made the existing listener-failure test
    flaky. Listeners are now an ordered slice keyed by subscription id; snapshot,
    unsubscribe-during-dispatch and panic isolation are unchanged.

## Resolved follow-up: angle autolinks and inline HTML

The first bare-autolink follow-up exposed loose angle/HTML recognition:
`parseAngle` accepted `<a:b>`, `<a@b>` and whitespace in URI bodies, while
`parseInlineHTML` accepted any `<letter…>` through the next `>`. Rejecting an
angle autolink alone was insufficient because the loose HTML fallback could
still claim it. Both now use the actual Marked 18.0.11 compiled rules inherited
by pi v1.4.0's `packages/tui/src/components/markdown.ts`.

`TestInlineHTMLRejectsMalformedAttributes` failed red with one HTML token for
`<see HTTP://Example.COM>` instead of text and a bare URL.
`TestAngleAutolinksRejectInvalidBodies` then failed red for the three invalid
bodies above. The fixes use explicit JavaScript whitespace and ASCII word
classes, the 2–32-character URI scheme rule, dotted email labels capped at 63
characters, and the reference tag/attribute, comment, processing-instruction,
declaration and CDATA alternatives. The email rule preserves the reference's
scheme-first precedence for URIs containing `@`.

A generator extracts the actual Markdown parser setup read-only from the
reference and loads its pinned Marked/CJK dependencies. All 171 fixtures pass
through public `ParseInline`. One fixture also caught Marked's `edit()` helper
stripping an unescaped caret from the source email class: Go initially linked
the address, but the actual configured reference produced text and pending
LaTeX. The compiled class, not the unexpanded source regex, is now followed.

Re-running the same 30,695-case corpus gives zero mismatches, including the
1,819 angle/HTML mismatches from the previous checkpoint. Regeneration of the
angle/HTML, Cloudflare-auth, OAuth token-auth and structured-content fixture
sets is byte-identical. `TODO.md` has no confirmed unresolved findings; the broader
review queue below still does not claim exhaustive coverage.
