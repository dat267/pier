# Startup optimization review, 2026-10-27

## Scope and verdict

Reviewed the pending catalog decoding, cached-model reads, session construction
and transcript-replay changes following `be1c065`. Reference: read-only pi
v1.4.0 (`4a080252f`). This is a review of the startup changes, not another
whole-codebase audit.

No blocking correctness finding remained in the optimization changes. The full
gate exposed one pre-existing flaky disposal-test fixture, CR-074 below. Its
repair changes only the test, not production cancellation policy.

## Boundaries checked

- **Embedded catalog:** the model alias avoids wire-model bookkeeping while
  raw compatibility settings remain separate until the enclosing API selects
  their type. Sampling insertion order is retained when parameter maps contain
  values; the catalog remains lazy. References: `ai/src/model-catalog.ts`,
  `providers/openai.models.ts`, `api/simple-options.ts`.
- **Model-store reads:** the reflection helper covers the current descriptor
  types: records, string-keyed maps, slices, pointers and scalars. Exported
  mutable fields are copied recursively. The only shared private fields are
  immutable model JSON provenance; serialization reads them and decoding
  replaces them. Writes keep their existing JSON validation, cancellation
  checks remain in place, and D271's empty-array shape remains unchanged.
  Reference: `ai/src/models-store.ts` (`structuredClone`). Future descriptor
  types outside these supported shapes will need explicit clone coverage.
- **Session construction:** checking the existing ID index avoids a history
  copy without changing D237's initial-tool declaration boundary. Snapshot
  preallocation preserves independent descriptor values and nil empty output.
  Reference: `coding-agent/src/core/session-manager.ts`, `getEntryCount` and
  `getEntries`.
- **Transcript replay:** only canonical message payloads borrow the owned
  decoded cache. Same-ID standalone or changed payload buffers fall back to
  independent decoding; synthetic entry factories are unchanged. Lookup
  releases the session lock before decoding. UI text/history remain original,
  not context-edit replacements, and model context is not mutated. Persisted
  assistant identity also restores cache-miss notice matching. The compaction
  status counts all persisted branches without copying history or adding a
  cached counter. References: `sessionEntryToContextMessages`,
  `buildContextEntries`, `buildSessionProjection` and interactive-mode.ts
  `renderSessionEntries`/`renderInitialMessages`.

## CR-074: disposal fixture raced a cancellation-ignoring success (resolved)

The first review `just check` failed in
`TestDisposeCancelsActiveBranchSummary`: a disposed navigation returned success
and persisted its fake summary. The fixture called `Dispose` inside its stream
function, then used `summarizingStreamFn`, which ignores the forwarded context
and emits a successful terminal event from a goroutine.

If that goroutine finishes first, `EventStream.Result` can return the already
completed success. A temporary fixture that waits for this successful result
before returning made the failure deterministic, 3/3 times, with both current
and HEAD session construction/manager code. This isolates the fixture race from
the optimizations. The pin's `ai/src/utils/retry.ts` also returns successful
producer results unchanged; a cancellation-aware provider must honor its
forwarded signal.

The repaired fixture explicitly checks that disposal cancelled the forwarded
context, then synchronously emits an aborted provider response. It retains the
aborted/cancelled outcome and no-persisted-summary assertions. Removing the
`Dispose` call in a negative control now fails directly on the context check.
The repaired test passed 200 times each at `GOMAXPROCS=1` and `8`. No production
abort semantics or documented divergence changed.

- Fresh-binary `just check`: passed after the fixture repair.
- Fresh-binary `go test -count=2 ./...`: passed, all 16 tested packages.
- Focused new regression tests: passed 20 times each at `GOMAXPROCS=1` and `8`.
- `just cross`: passed for all six cross-build/vet targets.
- `just reference`: passed at v1.4.0 (`4a080252f`).
- All 15 interactive golden families regenerated byte-identically.
- New model-store cloning versus the old JSON round trip: identical serialized
  bytes for all 1,598 built-in models and six additional cached catalogs.
- The source-generated model-store corpus remained byte-identical.
- `git diff --check`: passed.

Historical local measurements used fresh processes and a warm filesystem.
Catalog decoding fell from about 69 ms to 17 ms. A subsequent cached-model and
session-snapshot pass reduced fresh first-frame median from 63.06 ms to
49.21 ms and copied-session replay from 174.74 ms to 147.98 ms. The final replay
pass measured 149.04 ms versus 135.18 ms across 12 rotated/interleaved runs per
build. These are separate comparisons, not additive latency guarantees.

The tmux replay benchmarks used only a private copied 56 MB session, reset
before each run. Network, MCP, project resources and goal/tool execution were
disabled equally in both builds. No prompt was submitted and no live session
path was passed to the benchmark. Private session data and terminal captures
were not added to the repository.

No local race run was performed; CI remains the race gate. Cross-build/vet is
not an OS-runtime test, and the timings do not establish cold-filesystem or
full-MCP startup performance. No dependency installation, reference checkout
change, binary installation, push or release was performed during the review.

## CR-075: replace an environment-dependent allocation ceiling

Release CI run `40447600971` on `e066990` reported no data race, but failed both
race-enabled repetitions of `TestBranchPreparationAllocationsStayLinear`:
1,960,632 and 2,135,824 allocated bytes exceeded its 1,048,576-byte ceiling.
That ceiling assumed every decoder/runtime configuration stayed below 2 KiB per
message instead of directly testing the regression's scaling property.

The guard now compares 512 and 2,048 messages, with enough token budget to keep
both complete inputs and explicit chronological-order checks. Four times the
input may allocate at most six times as much, allowing linear decoder overhead
without accepting the old growing-slice prepend implementation. A saved
pre-CR-062 implementation fails the revised guard: allocations grow from
2,318,864 to 35,687,080 bytes. The current append-and-reverse implementation uses
64,112 and 281,184 bytes locally and passes 20 runs each at `GOMAXPROCS=1` and
`8`. No production code or CI gate was disabled. Releasing still requires a
green race-enabled CI run on the correction's exact commit.
