# Reproduced audit findings

- CR-175 (P2): session JSONL files are created mode 0666 (typically 0644) in directories mode 0777 (typically 0755), exposing conversation/tool output to other local users when parent paths are searchable; hardening would intentionally diverge from pi and needs approval.
- CR-176 (P2): D161's output-budget sweep can unlink a still-open, in-progress tool output file when a new log pushes existing scratch above 256 MiB. Same-process concurrent outputs are now protected; another pier process sharing the temp directory has a separate active-file registry and can evict it, leaving a stale path. Reproduced with two subprocesses sharing `TMPDIR`: a holder kept a truncated 256 MiB+ accumulator file open, then a second process created another accumulator and swept the holder's pathname. Pinned pi v1.4.0 (`packages/coding-agent/src/core/bash-executor.ts` and `core/tools/output-accumulator.ts`) does not sweep these files. Cross-process protection remains open.
- CR-180 (P2): untrusted message/tool text containing an OSC 52 clipboard sequence is passed through `tui.Text.Render` and `Renderer.ApplyLineResets` unchanged; a terminal that supports OSC 52 may overwrite the user's clipboard while rendering captured tool output. Reproduced by rendering a synthetic `safe + ESC ] 52 ; c ; Zm9v BEL + tail` string and observing the OSC 52 sequence in the final renderer line. The same control injection is possible in the window title: `Lifecycle.UpdateTerminalTitle` includes the session name and cwd basename, and `ProcessTerminal.SetTitle` inserts the value into OSC 0 without escaping. Pinned pi v1.4.0 (`packages/tui/src/tui.ts` `applyLineResets`, `utils.ts` `normalizeTerminalOutput`, and `terminal.ts` `setTitle`) also preserves these sequences, so mitigation is an intentional terminal-output security divergence and needs policy approval.
