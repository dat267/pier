# Reproduced audit findings

- **A521, medium:** a `supportsMessageThreads` compat entry in `models.json` is accepted and ignored. pi v1.5.2 (b4afdddf) `api/anthropic-messages.ts` sends Anthropic's `message-threads-2026-08-12` beta with a per-session thread id, hashes the unchanged prefix, records the thread the reply belongs to and starts a new thread when the provider rejects the old one; pier has none of that state, so the flag is a no-op and every turn re-sends the whole transcript. No shipped catalog sets the flag, so only a user override reaches it. Repair is a feature port (thread map with its bound, prefix hash, rollback, `new-thread` recovery), not a fix.

- **A522, low:** a session whose stored cwd is gone offers only Continue and Cancel. pi v1.5.2 (b4afdddf) `core/session-cwd.ts` and `interactive-mode.ts` also offer "Fork into <cwd> (new session ID, original kept)", which copies the session into the current cwd through `SessionManager.forkFrom` and drops the copy if a switch is vetoed. Pier has the fork primitive (`coding.ForkSession`) but both prompt wirings carry a binary `onCwd(cwd, ok)` answer, so porting needs one answer type plus the switch path.

- **A523, medium:** `pier auth login` is advertised by the port's own help and unknown-command message but not implemented: `pier auth login <provider>` exits with `Unknown auth command "login"`. pi v1.5.2 (b4afdddf) `cli/auth-login.ts` and `auth-terminal.ts` run it in the terminal (`auth login <provider> [--api-key] [--no-browser]`, provider matching, radius MCP planning); `auth logout` is ported. Repair is a CLI port over the runtime login path, not a fix.
