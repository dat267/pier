# Reproduced audit findings

- M140 (perf): pinned pi v1.5.0 `highlight.js` is faster than pier for an 8 KiB JSON-looking repeated-token input (`"0x"` × 4,096): warm Node benchmark 2.585 ms/op, while pier's unmodified Go path took 16.46 ms/op. A byte-buffer prototype reduced pier to 4.8 ms/op but still missed the reference and regressed a representative 8 KiB JSON document (2.8 ms vs 2.6 ms for the original Go path), so it was reverted. The representative document is already faster than upstream (2.6 ms Go vs 4.7 ms Node). This remains open; no behavior or performance patch accepted until the exact workload beats the reference without regressing representative highlighting. Benchmarks are in `internal/highlight/performance_bench_test.go`.

- M139 (perf): `GetContextUsage` and `ProjectedEntries` re-walk and re-estimate the whole compaction window on every call, and the footer is invalidated on every session event (including each streaming update). Measured at 40,000 entries: 9.6 ms per `GetContextUsage` and 4.6 ms per `ProjectedEntries`, so a long session pays that per paint while streaming. The resolved window and its token estimate depend only on the branch version, which the projection cache already tracks.
