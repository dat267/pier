# Reproduced audit findings
- **A541, low:** a saved settings file orders the keys of a nested object alphabetically instead of in the order they were set. pi v1.5.2 (b4afdddf) `core/settings-manager.ts` merges each save into the parsed JSON object, so a nested object keeps JavaScript property order: setting `terminal.showImages` then `terminal.clearOnShrink` writes `{"showImages":false,"clearOnShrink":true}`. `coding/settingsmanager.go` `persistScopedSettings` orders the top level by file order then declaration order but builds nested objects as Go maps, so `marshalSettingsMapIndent` sorts them (`{"clearOnShrink":true,"showImages":false}`). The settings file then differs from the reference's bytes whenever one nested object gains two or more keys. Reproduce with the setter corpus (set both keys, save, compare the file), then carry the nested order through: file order, then set order, then declaration order.
