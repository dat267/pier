# Reproduced audit findings

- M140 (perf): pinned pi v1.5.0 `highlight.js` is faster than pier for an 8 KiB JSON-looking repeated-token input (`"0x"` × 4,096): five warmed Node runs measured 1.90–2.01 ms/op, while pier's unmodified Go path measured 19.82–20.31 ms/op. A byte-buffer prototype reduced pier to 4.8 ms/op but still missed the reference and regressed an 8 KiB JSON document. A second prototype used source spans for contiguous mode text and a builder only for discontiguous fragments: it reached 3.89–4.57 ms/op on the slow case and 2.39–2.65 ms/op on representative JSON (2.32–2.51 ms/op baseline), with lower allocations, while preserving the long-input output test. It still lost to Node on the slow case and was reverted. Representative JSON remains faster than upstream (Go 2.32–2.65 ms/op vs Node 4.09–4.15 ms/op). This remains open; no performance patch accepted until it beats the pinned implementation on the reproduced slow case without regressing representative highlighting. Benchmarks are in `internal/highlight/performance_bench_test.go`.
